用自家猫咪制作桌宠 · v0.1.1

一、先了解制作方式
这是“参考照片 → 统一角色设计 → 动作帧 → 整理素材 → 接入程序”的流程。
当前版本没有上传照片自动换猫的按钮，也没有内置图片生成服务。
你可以用支持参考图片的图像生成工具制作 PNG，再使用本项目的源码调整、验证和打包。
只替换坐姿不会改变其他动作：未替换的走路、舔毛等仍然是原来的三花猫。

二、准备照片
准备清晰、自然光下的正面、左侧、右侧和背面照片，最好再有坐姿和站姿。
把照片放进 Reference_photo 文件夹。该目录默认被 Git 忽略，发布前仍要检查上传清单。
记录：脸型、耳朵形状、眼睛颜色、鼻色、毛长、尾巴、四只脚的花纹。
尤其区分“猫自身的左侧/右侧”与“朝画面左边/右边”，不要用自拍镜像当作真实侧面。
先确认方向与毛色，再开始生成，能减少后续返工。

三、先做角色设定，不要直接生成整套动画
先生成正面坐姿、朝左侧面和朝右侧面的同一角色。确认脸型和花纹后，把这三张作为后续固定参考。
示例提示词：

“参考附图中的同一只猫，生成用于 Windows 桌宠的卡通角色。保留它的脸型、短毛/长毛特征、耳形、眼色及左右不对称花纹。线条清晰，配色与参考一致，透明背景，无地面、无投影、无文字、无边框。完整身体、耳朵和尾巴都在画面内。正面坐姿，角色设计与后续侧面动作保持一致。请不要把左右毛色镜像。”

把短毛/长毛等描述换成自家猫的特征。先检查单张，而不是一次索要几十种动作。
阴影由程序绘制，素材不要带额外投影。看起来像棋盘格不等于真正透明，要检查 PNG 的 alpha 通道。

四、分组生成动作
建议顺序：坐姿眨眼 → 左右走路 → 转身坐下 → 舔毛 → 趴卧 → 奔跑 → 扑跃与玩耍 → 窗口动作。
每组都附上已确认的角色设定。左右动作分别生成，不能简单翻转代替另一侧。

动作提示词模板：
“严格保持参考角色的脸型、头部大小、躯干比例、左右花纹和画风。生成朝画面右侧的 8 帧循环行走。尾巴翘起，两组对角脚交替，支撑脚接触地面、摆动脚抬起向前。相机和角色比例固定，各帧使用同一个透明画布。不要逐帧把猫重新放大到填满画面。按 1 至 8 排列，最后一帧能自然接回第一帧；不把第一帧重复当作最后一帧。”

奔跑改为前后肢交替收拢、伸展的奔跑循环，保留适度脊背屈伸，避免身体忽长忽短。
“循环”指第 8 帧到第 1 帧也连续；除了正常速度，还要用 2 fps 检查脚序、头部和毛色跳变。
生成结果通常需要修正，不要因为帧数正确就直接接入。

五、最简单的接入：先替换坐姿
1. 下载仓库源码到一个新的目录，保留原项目作备份，安装 Windows Python。
2. 双击 start_cat.bat 验证原版能够启动，然后退出。
3. 打开 output/imagegen/idle-v3，先逐张看现有 frame-01.png 至 frame-06.png。
4. 用自己的 6 张同尺寸 PNG 替换这些文件，保持文件名、眨眼顺序与接触线一致。
5. 再次运行 start_cat.bat，右键关闭自主生活，观察坐姿与眨眼。

当前多数素材使用 512×512 透明画布，地面脚底参考 y=490；但窗口姿势有各自接触线。
坐姿和部分旧素材在运行时还会经过 idle_scale 缩放，当前值在 turn-sit-v1/animation.json 中。
应以“程序最终显示”为准：不要先把原图缩到与显示图一样小，又被程序再缩一次。
不要用统一外接矩形高度去缩放所有动作，趴着本来就应比坐着矮。

六、扩展到其他动作
程序加载路径以 desktop_cat.py 中的定义为准，常用目录如下：
- idle-v3：坐姿与眨眼。
- groom-v1：舔爪。
- walk-diagonal-left-v1 / walk-diagonal-right-v1：默认左右走路。
- turn-sit-v1：左右转身坐下各两张图。
- rest-idles-v1/prone、supine、side：趴着、仰躺、侧卧。
- interactions-v1/held、perch：抱起和趴窗沿。
- window-actions-v1：骑窗沿、跳下。
- window-climb-v1、window-climb-back-v1、window-climb-side-v1：攀爬。
- hunt-actions-v1：run_left、run_right、pounce_left、pounce_right、play_kick、play_lick。
另有旧版走路和 deform 资源供菜单切换；需要全套换猫时也要替换。

每个 animation.json 中的 frames、播放顺序、帧时长、接触点、支撑脚等应与新图匹配。
替换相同构图的帧可以保留结构；若改变脚的位置或帧数，就不能照搬原来的支撑脚数据。
走路的脚掌锚点见 anchored_walk.py 及对应 animation.json；跑步的速度和步幅见 run_animation.py。
动作整体校准在 sprite_scale.py；奔跑每帧肩胯参考在 run_shape.py，新猫必须重新量取。
默认窗口尺寸为 220 个逻辑像素，与原图的 512 像素画布不是同一个概念。

tools/package_*.py 是现有素材的制作脚本，部分裁切框、帧序和坐标针对当前三花猫写定，
不是任意图片的通用导入器。先阅读脚本、调整裁切框与坐标，再运行，避免覆盖好不容易整理好的素材。

七、眼睛跟随（可选）
默认关闭，右键勾选“目光跟随（眼眶内）”可开启。
新猫默认保持关闭即可使用原画眼睛。要启用跟随，必须重新标注每帧眼睛区域、闭眼帧和头部角度。
assets/eye-catalog.json 保存眼睛区域；部分新动作优先使用 animation.json 中的 eye_rects。
tools/catalog_eyes.py 可辅助生成标注，但现有颜色识别偏向当前猫的黄绿色虹膜，蓝眼或深色眼睛不能直接套用。
它还含有原猫的手工修正，需要清除或重新标注。闭眼、背面帧应为空数组。
eyes.py 中的奔跑侧脸角度参考也需更新。逐帧检查眼睑没有被盖住、蒙版没有碰到毛色、虹膜没有越界。

八、检查与打包
建议先在右键菜单里逐项试播，检查：
- 左右毛色正确，头身大小一致，耳朵、尾巴没有出画布。
- 循环首尾没有跳变，支撑脚不明显滑动，跑步帧频与位移对应。
- 坐下、起身、抱起、窗沿动作的落脚线正确。
- 眼睛跟随开启/关闭都正常，眨眼时没有残留瞳孔。
- 在不同缩放的屏幕之间反复移动，大小菜单仍然有效。

构建建议使用 Windows x64 Python 3.12 或更新版本。在项目目录用 Windows PowerShell 执行：
  .\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
  .\.venv\Scripts\python.exe -m pip install Pillow
  $env:QT_QPA_PLATFORM = "offscreen"
  .\.venv\Scripts\python.exe -m unittest discover -q
  .\.venv\Scripts\python.exe tools/audit_sprite_sizes.py
  Remove-Item Env:QT_QPA_PLATFORM
  .\.venv\Scripts\python.exe tools/build_release.py --version v0.1.1
  .\.venv\Scripts\python.exe tools/check_release.py release/XiaoMan_theCalicoCat-v0.1.1-windows-x64.zip

预览在 output/size-audit，免安装 ZIP 在 release。修改角色后，针对原猫像素/标注的测试也可能需要重新编写；不要直接删除失败测试而不检查原因。
完整解压 ZIP 到另一个目录试运行，再分享给别人；不要只分享 EXE 而遗漏 _internal。
要发布自己的版本，可以 fork 仓库、提交代码和运行素材，再在自己的仓库上传 ZIP。
不要提交 .venv、proxy.local.bat、私人原图或工具密钥；当前 .gitignore 已排除常用本地文件。
